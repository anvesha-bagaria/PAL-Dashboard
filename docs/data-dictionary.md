# Data dictionary

All data is **synthetic and fictional**, generated by `tools/generate_data.py` (fixed seed `20261015`). Files live in `data/`. The same content is bundled in `data/pal-data.js` as `window.PAL_DATA = { meta, schools, students, curriculum, progress, activity, diagnostics, pipeline, health }`.

Dates are ISO strings (`2026-10-15`). The dataset's "today" is `meta.as_of` = **2026-10-15**; the activity window is 60 days (`2026-08-17` … `2026-10-15`).

## Relationships

```
schools 1 ── * students 1 ── * progress * ── 1 curriculum.concepts * ── 1 curriculum.chapters
schools 1 ── * activity (one row per school per day)
schools 1 ── 1 diagnostics
curriculum.edges: concept → concept (prerequisites)
pipeline.books 1 ── 1 curriculum.chapters
```

## progress.json (4,264 records; one per student × concept touched or assigned)

| Field | Type | Notes |
|---|---|---|
| student_id, school_id, class_name, section | string | Denormalised for easy filtering |
| subject, chapter_id, concept_id | string | FK → curriculum |
| practice_attempts, practice_correct | integer | correct ≤ attempts |
| warmup_attempts, warmup_correct | integer | Warm-up / diagnostic-style answers |
| challenge_attempts, challenge_correct | integer | Challenge **answers** (5 per try) |
| challenge_tries | integer | 0–3 challenge attempts |
| challenge_passed | boolean | Pass = at least 3 of 5 correct in a try |
| tries_to_pass | integer \| null | 1–3 when passed |
| upi_score | number \| null | **Mastery Score**, 0–1; **null = not started** (assigned but no answers) |
| avg_time_sec | number \| null | Average seconds per answer |
| last_activity | date \| null | |

Invariants a test can rely on:
- `upi_score` is null **iff** `last_activity` is null **iff** all attempt counts are 0.
- `challenge_passed` ⇒ `upi_score` ≥ 0.85 and `tries_to_pass` between 1 and `challenge_tries`.
- Not passed ⇒ `upi_score` < 0.89; a row with `challenge_tries` = 3 and not passed is "stuck on challenge".
- `challenge_attempts` = 5 × `challenge_tries`.
- Σ answers over a school's rows = Σ `answers_*` over that school's `activity` rows.

## pipeline.json

| Part | Fields |
|---|---|
| stage_names | `S1` … `S5` → label |
| books[10] | `id`, `chapter_id`, `title`, `pages`, `last_run`, `stages.S1…S5` each with `status` (`completed`, `running`, `failed`, `pending`) and `minutes`; stage extras: S1 `elements`; S2 `los`, `concepts`; S3 `edges`; S4 `questions_tagged`, `content_tagged`; running stages have `progress_pct`; failed stages have `error` |
| question_bank | `total`, `by_source{cms_bank, ai_generated}`, `verified{verified, unverified}`, `by_difficulty{low, medium, high}`, `by_chapter{chapter_id: count}`; `by_source`, `verified`, `by_difficulty` and `by_chapter` each sum to `total` |
| generator | 30-day funnel `requested`, `returned`, `passed_schema`, `passed_katex`, `saved_to_cms`; `failures{schema_invalid, katex_invalid, cms_save_failed, duplicate}`; `providers{external, self_generated, template_fallback}` (sums to `returned`, not `requested`) |
| llm_usage[6] | `stage`, `calls`, `tokens_m`, `p50_ms` |

The data contains exactly: one book with a **failed** stage (S4), one **running** at S2 (62%), one **running** at S1 (35%), the rest completed.

## Edge cases the dashboard must handle

| Case | Where |
|---|---|
| School with 0 learners (S106) | schools, sync, comparisons |
| Students with no activity (null `last_active`) | students tab, KPIs |
| Concepts not started (`upi_score` null) | status bands, averages |
| Failed and running pipeline stages | pipeline tab |
| Rows where accuracy would divide by zero | KPIs |
| Filters that leave no rows | every tab shows an empty state |

## Regenerating

`python3 tools/generate_data.py` rewrites every file above and `pal-data.js`. Output is deterministic; if you change the generator, update this document and the data tests.
